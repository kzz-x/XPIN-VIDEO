# 01｜原文 → 分镜（GPT）

**输入：** 原文、画幅/平台、参考、已有项目（有则沿用）；没有音频时不假定精确时码。

1. 读完整篇，按**视觉意群**拆镜，而非每句话机械一镜。先确定信息关系（对比、因果、变化、整体/局部或证据）、转折、节奏及镜头联系；多个知识点可共享一个连续视觉过程，不为每句口播强行切镜。
2. 识别用户括号标注：`（三维）`、`（二维）`、`（素材）`、`（元素）`、`（片段/CGI）`、`（实拍）` 等；标注优先；段后标注作用于前一意群，独立段前标注作用于后一意群，除明确全片设置外不跨镜继承。未标注则按画面质量、工期、可修改性与复用价值选最合适的媒介，必要时组合（例如先素材后二维包装）。已确认的局部媒介与禁项在后续版本继续有效。
3. 把镜头评为 **S**（开场、核心记忆点）、**A**（重点解释）、**B**（过渡/辅助）；好钢用在 S/A，不把全部镜头做成复杂动画。
4. 每镜只输出必要字段：`编号｜原文范围/信息目标｜视觉内容及主动作｜类型/拟用路线｜预估时长/节奏｜衔接或转场｜素材/真实性缺口｜S/A/B`。需要时添加关键画幅；避免密密麻麻的长分镜表。
5. 有口播/音频/字幕用真实节拍和停顿；仅有原文按口播字数**粗估**时长（可暂按约4–5字/秒起步，复杂解释留读图时间）。将事件点写成建议 Marker，便于后续逐镜微调。
6. 顺手给全片一段**简短剪辑节奏建议**：快慢层次、重点停顿、音乐情绪与关键音效落点，不替代后期详细方案。

**交付：** 全片镜头总览 + 值得重点设计的 1–3 个镜头 + 待核验的少数问题；对明显适合沉淀的镜头顺手标记可复用模板/组件，不为普通镜头强行模板化。全文交付止于分镜设计；明确请求直接制作时可以继续相应阶段。长片按镜头编号维持状态，用户只改某镜就不重做全篇；说「继续/剩下的」先按现有镜头状态与授权范围计算，不把未设计/未授权镜头直接当制作任务。多镜制作共享一份短全局 Brief，子任务只拿当前镜头卡与衔接约束；可独立则并行，有前置依赖则顺序执行，返工只影响本镜。
