# 04｜审片、节奏、声音与交付

**验收顺序：讲对 → 一眼看懂 → 像参考一样好看 → 真正可编辑/导出。** 先查当前镜头的主视觉、结构、排版、材质光照、Motion、镜头连续性和真实性。不要只看静帧：优先取 Marker 前后、主动作峰值与停留帧检查，兼顾起/中/末、衔接、穿模、焦点、闪烁、标注跟随、遮挡与循环接缝；静帧不能替代连续预览中对速度、错帧与运动模糊的判断；失败先修最重要问题，别叠滤镜。镜头整齐但像模板也算失败：优先提升构图、运动主次或 Hero Moment，而非只修技术 Bug。

**音画剪辑：** 先读全稿，以去口误、赘词和重复的 A-roll/口播建立剪辑主时间线，再按信息重点插入真实素材、录屏、CGI/动效及必要过渡，最后统一声音、字幕与节奏；重点开场/结论多给审美时间，解释段留足读图空间。口播关键词、停顿和呼吸控制切点；没有口播按估时，留读图停顿。音乐服务情绪与强弱，音效只打在出现、碰撞、组装、扫描、转场、结论等有因果的动作点，控制密度和人声可懂度。统一 Marker/Beat，方便 PR/AE 后期改速、挪节拍、接前后镜头；前后镜头不应各自无故重置运动状态；宏观进入微观、拆解再重组时保留可追踪的对象/接点、空间方位和主光逻辑，避免无说明地换模型或镜头方向。素材、图表与 CGI 的证据等级分别检查：剪辑画面不自动证明文案事实；概念模型/厂商 CGI 不冒充实拍；数据标注不得改变原始口径。录制真实设备/软件操作前先清理桌面与通知，核对设备、操作路径、画幅/字清晰度，指针或触摸高亮只在帮助理解时使用。PR/字幕类重复劳动优先走文本转录、剪辑点/静音识别与批量整理；字幕校对去无信息口头语、按语义断句、核专名/单位，同时保留原时间码和已锁定文字策略。

## 输出顺序

1. **关键帧：** 几张代表静帧对照目标参考，没达标先不精渲。
2. **快速预览：** 只输出指定镜头/短样片，约 540–720p、低采样，目标计算用时不超过 10 分钟；超出就缩段或降低预览成本并告知。
3. **正式成片：** 用户批准或明确要求后才启动完整高质量渲染。

| 质量档位 | 默认目的 |
|---|---|
| 快速 | 540–720p / 简化特效 / 审动态与音画，优先 ≤10min |
| 标准 | 常用 1080p / 目标帧率 / 合理抗锯齿、采样与降噪 |
| 成片 | 实际交付分辨率/帧率，按需 4K、景深/运动模糊、准确色彩/Alpha/音频与高质量编码 |

渲染前核查画幅、fps、色彩、文字安全区、编码/容器、音轨、输出位置。用实际短段测速估算总帧时长；没有数据就只给**粗估范围**，不能伪称实测。正式片先导出本地、打开真实文件核对播放、帧数/时长、音画同步及画面，再同步共享盘/NAS，避免直接网络导出未完成就误报交付；网页录制还需检查 DOM/SVG/WebGL、字体和混合层是否真的录入，以及容器/编码是否匹配，不以改后缀冒充转换；线条锯齿/闪烁从采样与抗锯齿修复，不能靠码率掩盖。

**开启长渲染后不要傻等。** 后台渲染只在已确认脱离会话后仍持续的情况下启动并记录任务/日志/输出位置与 ETA，随后结束当前轮次；不支持可靠后台则如实告知启动与恢复方式。不能说「后台已经在渲染」却实际没有启动。

完成时只报：文件/工程路径、渲染档位、**已核/失败/未测**、最多三个待修问题；区分源码/构建、交互运行、GPU 实际画面、文件下载与解码、目标机器性能的证据等级，不能用编译通过或生成 Blob 冒充真实成片验收；只更新当前镜头状态。审核必须对应当前镜头/文件版本与实际画面；返工后重审，旧版 PASS 或旧截图不得沿用。AI 片段查首中末的身份/数量/光源连续性；元素查 Alpha/拆分实际文件；可编辑工程查改值生效与保存重开，不以截图/面板按钮代替功能。
