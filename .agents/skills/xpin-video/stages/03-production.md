# 03｜制作与工程修改

按**当前交付物及实际依赖**选用对应媒介要求。复杂镜头先锁视觉目标与主体运动，可用灰盒预演验证关系和路径；重点镜头逐个达标。

## 工程保护与执行

- **已有工程：** 先读取相关场景、对象、动画及依赖；修改前在原目录外备份可恢复版本，保留未保存的人工改动。仅修改目标范围，保护其他素材、关系、关键帧和参数；改后回读验证。中断或失败先检查现有产物，再决定续做或返工，避免旧结果覆盖新成果。备份不可恢复时先停止写入。
- **新制作：** 根据镜头和输出格式选择结构。共享运动建立正确的父子或跟随关系，局部偏移独立控制；复杂度以实际需要为准。
- **现有模板：** 在副本中开发，核对必要依赖，保留已有可用功能；按当前工具实际能力执行。

## 按交付物选择

- **硬件结构 / GLB：** 依据可信资料还原具体型号、零件比例、位置、连接和装配关系，重要部件独立命名、轴心正确。需要拆解时，将装配、拆解与复原做成可调用的标准 glTF 动画 Clip；重新加载验证结构、材质、动画与时间定位。后续科普交互可复用同一模型，视觉渲染独立于结构资产。
- **AE：** 简单动画优先原生图层和效果，复杂关系再用父子级、预合成、表达式或脚本。读真实工程状态后用稳定标识结合合成名、图层名/类型定位目标；保持可编辑与中文可见命名。使用 Engine Room 时先启动 AE 并确认连接，再启动 PR。
- **Blender：** 保持对象层级、材质、动作和关联关系清楚；按需要使用父子、约束、Driver、F-Curve 与摄影机 Rig。需要交付可编辑工程时，将关键控制数据保存在工程中，保证保存重开仍有效。
- **HTML / Three.js：** 场景、交互、时间线和输出共享一致的状态与时间源；支持准确的播放、暂停、Seek 与可重复渲染。需要编辑功能时提供真正可保存、恢复的状态；需要录制时验证纯画面输出和逐帧一致性。依交付需求处理文件打包与离线依赖。
- **数据与素材：** 图表采用可追溯、可替换的数据及正确单位和口径；外部素材核实来源与使用范围。独立元素保留合成所需的透明度、层级、轴心和替换能力，示意内容清楚标识。

## 动画、控制与验收

- **Motion：** 先确保主体结构、空间关系、转轴和运动路径正确，再设计缓急、错落、停顿、跟随与镜头调度；共享动作集中控制，个体运动保留可调空间。视觉与节奏服从叙事，不机械套用预设。
- **口播同步：** 以实际使用的音频区间及现有 Marker 对齐动作；需要补点时按语义和停顿设置节拍。多镜头或预设切换时维持姿态和时间状态连续。
- **可编辑控件：** 将后续可能需要调节的重要参数开放给用户；高频项前置、其他参数分类折叠，中文命名并实时预览。优先复用工程已有控制关系。
- **Codex 执行：** 任务说明只传达当前目标、确认的参考与素材、核心动作、交付格式和验收标准；局部修改另明确保护范围，技术实现保留自主选择。
- **验收：** 依据实际产物检查事实、画面、运动、交互与可编辑性；结合关键时刻截图和真实播放判断质量。遇到问题定位根因，只返工受影响部分；如需改变已确定的核心交付要求，先征得确认。
